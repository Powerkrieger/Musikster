# Musikster

A personalized [Hitster](https://hitstergame.com/)-style party game, originally built as a one-off
birthday present and since generalized: one build per person, each with their own name, greeting, colors
and deck of favorite songs. Physical cards (one per song, printed from a script) + a phone that
plays the song. Players build a timeline by guessing each song's release year — the app never
shows the answer on screen, so it's safe to have visible on the table.

---

Everything that's specific to one person lives in `people/<slug>/`, and **the whole `people/`
directory is gitignored here** — names, greetings, playlists, photos and song lists are personal
data and this repo is public. Each `people/<slug>/` is instead its own **private repo**
(`musikster-<slug>`), cloned into place; only `people/person.example.json` (the template) is
tracked in this one.

| File in `people/<slug>/` | What |
|---|---|
| `person.json` | name, app name, greeting, Spotify playlist, card-id prefix, colors |
| `overrides.csv` | manual release-year corrections for that playlist (optional) |
| `face_original.*` | the person's photo as received (optional) |
| `face.png` | generated by `scripts/make_contrast.py` from it: a posterized portrait composited into the middle of every QR code (a plain photo dropped here works too) |
| `assets/<slug>-deck.json.gz` | generated by `scripts/build_deck.py`; the one deck file — sent to people for "Import Deck" and bundled into the person's build |
| `print/*.pdf` | generated by `scripts/build_deck.py` (the printable card sheets) and `scripts/make_manual.py` (the one-page A5 manual/birthday card, German: greeting, app/Spotify/deck/rules, a QR code for the releases page and the deck's year chart; personal bits from the `manual` key in `person.json`) |
| `stl/` | generated by `scripts/make_box.py` / `make_tokens.py` / `make_plate.py`; the 3D-printable box and game tokens with their name/initial (optional) |

`app/build.gradle.kts` turns each of those directories into a Gradle **product flavor** of the
same name with `people/<slug>/assets/` as its assets dir, so `assembleNilsRelease` is
Nils's app, `assembleMayaRelease` would be Maya's. Because `people/` only exists on the
machine of whoever set things up, **personal builds are made locally**; a clone without any
`people/<slug>/` (including CI) builds a single generic `musikster` flavor instead — no greeting,
no bundled deck, but it imports any deck. All flavors share one package name
(`de.powerizzle.musikster`) and one Spotify registration; the trade-off is that only one build can
be installed on a phone at a time — which is fine, since the phone can hold **several people's
decks at once** (see [Playing with more than one deck](#playing-with-more-than-one-deck)).

## If you just want to play

No building, no Android Studio, no Spotify dashboard. Either install the personal APK you were
given (`musikster-<name>-release.apk`, your deck already inside), or grab the generic
`musikster-musikster-release.apk` from [Releases](../../releases) and use **"Import Deck"** on
the Home screen with the `<name>-deck.json.gz` file you were sent (see [Building a deck](#building-a-deck)
for where that file comes from). Adding someone else's deck later works the same way.

## Adding a person

1. Create a private repo for them and clone it into `people/<slug>/` — `slug` is lowercase
   letters/digits (it becomes the flavor name, the deck id and the card-id prefix):
   ```
   gh repo create musikster-<slug> --private --clone
   mv musikster-<slug> people/<slug>
   ```
   (Or just `mkdir people/<slug>` and `git init` in it later — the outer repo ignores whatever
   is in `people/`, nested repos included. No submodules involved.)
2. Copy `people/person.example.json` to `people/<slug>/person.json` and fill it in:
   ```json
   {
     "name": "Nils",
     "appName": "Nils' Musikster",
     "greeting": "Happy Birthday, Nils! 🎉\nEvery card is one of your favorite songs — good luck building the timeline!",
     "playlist": "https://open.spotify.com/playlist/…",
     "palette": ["C2185B", "6A1B9A", "1565C0", "00695C", "E65100", "2E7D32"],
     "printGradient": [[72, 209, 121], [46, 176, 155], [46, 108, 214]]
   }
   ```
   - `appName` defaults to `"<name>'s Musikster"`, `greeting` to empty.
   - `boxLabel` and `tokenLetter` (not shown) only matter if you 3D-print the box and game
     tokens — see [Printing notes](#printing-notes). `boxLabel` is the text engraved on the box,
     `\n` for the line break; defaults to the German possessive, `"<name>s\nMusikster"`
     (`"Nils'\nMusikster"` for names ending in an s sound). `tokenLetter` is the initial engraved
     into the tokens; defaults to the first letter of `name`.
   - `palette` is the set of colors the app's per-round background gradient is drawn from
     (RRGGBB hex); `printGradient` is the card backs' gradient as RGB stops. Both optional.
   - `bundleDeck` (not shown, default `true`): `false` builds the app *without* the deck. The
     person then gets `people/<slug>/assets/<slug>-deck.json.gz` (written by `build_deck.py`) and
     loads it once with "Import Deck", which is also how they learn to pass it on.
   - `cardIdPrefix` (not shown) defaults to `"<slug>-"`, so Nils's QR codes read `nils-001`,
     `nils-002`, … Only the very first deck sets it to `""` — its cards were printed before ids carried
     a prefix, and the printed cards must keep matching. Don't do that for anyone new: unique
     prefixes are what let decks be mixed together.
3. Optionally drop a photo at `people/<slug>/face_original.jpg` (any size/aspect) and run
   `uv run make_contrast.py <slug>` in `scripts/` — it finds the face, cuts the background
   out and flattens the portrait to three tones, writing `face.png` for the QR codes. Or skip
   the script and put any square-ish photo at `people/<slug>/face.png` directly.
4. Sync Gradle (Android Studio picks up the new flavor) and run
   `uv run build_deck.py <slug>` — see [Building a deck](#building-a-deck).
5. Build the flavor: `./gradlew assemble<Slug>Release`, or select it in Android Studio's
   Build Variants panel. This has to happen locally — CI never sees `people/`, so it only
   produces the generic build. For a signed release build set `KEYSTORE_PATH`,
   `KEYSTORE_PASSWORD`, `KEY_ALIAS` and `KEY_PASSWORD` in the environment (see
   `app/build.gradle.kts`); the APK lands in `app/build/outputs/apk/<slug>/release/`.
6. Commit and push `people/<slug>/` to its private repo — that's the only copy of the
   greeting, the overrides, the photo and the deck. (A `people/<slug>/.gitignore` with `print/` and
   `stl/` in it keeps the ~11 MB of PDFs and the meshes out of that repo; they regenerate in seconds.)

## Developer setup (building from source)

### 1. Spotify Client ID
The app needs `BuildConfig.SPOTIFY_CLIENT_ID` (read by `SpotifyAuthManager.kt`) to talk to Spotify.
It comes from one of two places, whichever is set:
- **CI builds** (GitHub Actions, see `.github/workflows/build.yml`) read it from the
  `SPOTIFY_CLIENT_ID` repo secret — already configured, nothing to do for a normal release build.
- **Local builds** (Android Studio, or running `scripts/build_deck.py`) read it from
  `local.properties` (gitignored, never committed):
  ```
  SPOTIFY_CLIENT_ID=your_client_id_here
  ```
  Ask Joost for the value, or create your own app at https://developer.spotify.com/dashboard —
  under **Settings → Edit** you'd need:
  - **Redirect URIs:** `musikster://callback` (app login) and
    `http://127.0.0.1:8927/callback` (deck-building script login)
  - **Android Package Name:** `de.powerizzle.musikster` (the flavors all share it)
  - **Android Package Fingerprint (SHA-1):** your keystore's SHA-1 (`~/.android/debug.keystore`
    for local debug builds; the release keystore's for anything you intend to distribute)

### 2. Spotify App Remote AAR
Already included in `app/libs/spotify-app-remote-release-0.8.0.aar` (copied from the QuickMusicQuiz
project). If you ever need to update it, download a newer release from
https://github.com/spotify/android-sdk/releases and replace the file (update the filename
reference in `app/build.gradle.kts` too if the version changes).

### 3. Build the deck
Deck building happens **outside the app**, once per person, on your computer — see
[Building a deck](#building-a-deck) below.

## Building a deck

A one-time (or whenever-the-playlist-changes) script, not part of the app:

```
cd scripts
uv run build_deck.py <slug>              # playlist from people/<slug>/person.json
uv run build_deck.py <slug> <playlist>   # …or override the playlist for this run
```

(`uv run` installs the pinned dependencies from `scripts/pyproject.toml`/`uv.lock` into a local
`.venv` on first run — see https://docs.astral.sh/uv/ if you don't have `uv` installed.)

1. It opens your browser for a one-time Spotify login (same client id/account as the app), then
   reads every track in the playlist via the Spotify Web API. A development-mode Spotify app is
   only allowed to read playlists *you* own; for someone else's **public** playlist the API
   returns 403 and the script falls back to the playlist's public embed page, which lists the
   same tracks (minus album art, which the app never shows anyway).
2. It looks up each song's release year via the free iTunes Search API. Some matches are wrong
   (reissues, compilations, etc.) — put corrections in `people/<slug>/overrides.csv` (`key,year`
   rows, where `key` is either the Spotify track id or `Song Name|Artist Name`) and rerun.
3. It writes **`people/<slug>/assets/<slug>-deck.json.gz`** — the one deck file, gzipped JSON
   (~9 KB for 120 cards, ~5x smaller than plain). Gradle bundles that directory into the
   flavor's APK, so **rebuild and reinstall the app** after running the script to pick up a
   new/changed deck — or just send the file (see below). Every card id is prefixed with the slug (`nils-001`) so decks from different
   people never collide.
4. It renders three printable PDFs into `people/<slug>/print/`: `musikster_<slug>_deck.pdf` (the
   card front/back sheets), `musikster_<slug>_line_sheet.pdf` (the cutting guide, printed once on
   plain paper), and `musikster_<slug>_deck_with_line_sheet.pdf` (the deck with the cut guide
   appended as its last page, for sharing/printing as a single file). Print the deck, then cut the
   cards out against the line sheet (see Printing notes below).

**Card design:** the QR-code (front) side is standardized — plain white, only the QR code itself
changes card to card. If `people/<slug>/face.png` exists it's recolored into the person's
`printGradient` and composited into the center of every QR code (high error-correction is used
so the code still scans with the photo covering the middle). Without that file, the QR is plain.
`scripts/make_contrast.py <slug>` makes that file from `face_original.*` as a screen-print
style portrait — face-centred crop (OpenCV YuNet), background removed (rembg), three flat tone
bands on a filled disc — which reads far better at QR size than a tinted snapshot. It also
writes `photo-contrast.png`, the black/red/white posterization the archived relief pipeline
(`scripts/archive/make_heightmap.py`) used to need drawn by hand. Both models download on the
first run (~170 MB for rembg). The answer (back) side uses the
person's `printGradient` (green-to-blue by default) with title/artist/year.

Because the deck lives in the APK's assets, reinstalling the app (same build) restores it —
there's no separate backup step needed.

**Sending a deck to someone else's build:** the deck file lives in the gitignored `people/` (it's
a personal playlist, not source), so anyone who builds the app from a clone of this repo won't
have it baked in. Instead of rebuilding, just send them `people/<slug>/assets/<slug>-deck.json.gz`
(AirDrop, email, whatever); the app's Home screen has an **"Import Deck"** button that opens a
file picker, validates the file, and stores it in app-private storage — no rebuild/reinstall
needed. Importing a deck whose id matches one already on the phone (including the built-in one)
replaces that copy, which is how an updated deck gets to someone. See
`app/src/main/java/de/powerizzle/musikster/DeckRepository.kt`.

It's plain gzip (not a `.zip` archive): "Import Deck" detects that and decompresses it, no
unzipping needed on the other end, and a plain `.json` deck imports too. (Android's build tools
unpack `.gz` assets on their own, so inside the APK the bundled copy shows up as
`<slug>-deck.json`; the app accepts either name, and an old build's `deck.json` as well.)

**Bulk-adding tracks:** `scripts/add_to_playlist.py` adds a batch of tracks to a playlist you own,
without leaving the terminal — handy when you've curated a list faster than you can add them by
hand in Spotify. Put `artist,title` pairs (one per line) in a CSV and run:
```
uv run add_to_playlist.py <playlist URL or ID> tracks.csv
```
It searches Spotify for each pair, shows you what it resolved to, skips anything already in the
playlist, and asks for confirmation before writing anything. Rerun `build_deck.py` afterwards to
pick up the additions.

## Playing with more than one deck

The Home screen lists every deck on the phone — the one built into the APK plus any imported —
each with a switch. Cards from every switched-on deck are recognised when scanned, so two
siblings' decks can be physically shuffled into one pile and played as a single game; switch a
deck off to take its cards out of play without deleting it (imported decks can also be removed).
The count of cards in play is shown above the list.

The only requirement is that no two decks in play share a card id, which the deck builder
guarantees by prefixing ids with the person's slug. The one exception is the very first deck
(bare `001`…); if a second deck with unprefixed ids is ever switched on next to it, Home shows a
warning and those cards would play the wrong song.

**Play**
1. Scan a card's QR-code side with the in-app camera.
2. The song plays through the Spotify app on this phone (App Remote SDK — needs Spotify Premium
   and the Spotify app installed). Pause/resume from here.
3. Players place the card in the timeline by guessing the year, then flip it to check the printed
   answer — the app screen never shows it.
4. **Scan Next Card** to continue.

### Hiding the song title

The app itself never shows the answer, but *Spotify* does: while a track plays, the Spotify app
posts its own media notification naming the song, which is exactly what players are meant to
guess. No app can suppress another app's notification, so the fix is to keep it off-screen:
in `MainActivity.onCreate`, the game runs full-screen with the system bars hidden and the screen
kept awake — there's no status bar for the notification to appear in, and the phone never times
out into a lock screen showing the same media card. Swiping in from the screen edge still reveals
the bars, so this hides the title rather than locking the phone down.

Turning Spotify's notifications off in Android settings (Settings → Notifications → App
notifications → Spotify) looks like the cleaner fix, but it **doesn't work** — tried on the
Samsung/One UI game phone and the media card kept showing. It's driven by the MediaSession, not
by the app's notification permission, so the in-app full-screen approach is what actually does it.

## Printing notes

- Cards print as a 3×4 grid per A4 page (12 cards/page). Front (QR) sheets are plain white; back
  (answer) sheets use the green-to-blue gradient. `musikster_<slug>_line_sheet.pdf` is a single
  page of light gray cut guides at the same grid positions — print it once on plain paper and lay
  each printed card sheet underneath it to cut against.
- Back sheets have their card columns mirrored, so a standard duplex print job set to
  **"flip on long edge"** should line up each card's QR side with its answer side once cut out.
  **Print a single page first** and check alignment before committing to the whole deck — this
  can't be verified without a real printer, and printers vary in their default duplex flip
  direction. If your printer instead flips on the short edge, mirror the rows instead of the
  columns (swap the `reversed()` grouping in `scripts/build_deck.py`'s `generate_pdf()` from
  per-row to per-column).
- **3D prints** (optional — the models, their origins and print settings are in
  [`3d/README.md`](3d/README.md)). Both scripts need the Z003 font from `fonts-urw-base35`, write
  a PrusaSlicer project into `people/<slug>/stl/` plus a `_preview.png` to eyeball, and leave
  everything but the engraving exactly as in the template:
  - **Game tokens:** `uv run make_tokens.py <slug>` engraves the person's initial into the coin.
    Print the result **32 times**.
  - **Card box:** `uv run make_box.py <slug>` engraves the person's `boxLabel` on the lid and the
    bottom of the box, shrinking it if a long name wouldn't fit. Print once.
  - **Both on one plate:** `uv run make_plate.py <slug>` puts the box and 32 tokens on one Core
    One plate in three colours with the two filament swaps already set (hand, then body and lid,
    then rails and the rest of the tray).
  - `scripts/archive/` holds the earlier helpers (a generated box and token, and a
    photo-relief keepsake pipeline); see its README.

## Known limitations

- iTunes' free search API has an informal rate limit; looking up ~100 songs' release years is
  paced with a small delay and can take a few minutes.
- No digital timeline/scoring — by design, players self-referee like the real board game.

## Architecture

Same deliberately simple shape as `QuickMusicQuiz`: one Activity, Jetpack Compose, no DI, no
navigation library. `MainViewModel` holds a sealed `AppMode` and owns `ScanPlayViewModel` (a plain
state-holder class sharing its coroutine scope, not a separate Android ViewModel) — avoids a
custom `ViewModelProvider.Factory` for what's a single-screen-per-mode app. Deck building
(playlist fetch, year lookup, QR/PDF generation) lives entirely in `scripts/build_deck.py`, not in
the app — see [Building the deck](#building-the-deck).

| File | Purpose |
|---|---|
| `MainActivity.kt` | Single activity; root Compose UI; App Remote + OAuth redirect lifecycle |
| `MainViewModel.kt` | Top-level `AppMode` state; auth; owns the managers below |
| `SpotifyAuthManager.kt` | PKCE OAuth; token storage |
| `SpotifyPlaybackManager.kt` | App Remote SDK wrapper (play/pause/seek/art) |
| `DeckModels.kt` / `DeckRepository.kt` | Card/Deck data + the set of decks in play: the flavor's bundled `assets/<slug>-deck.json.gz` plus any imported ones, each toggleable |
| `ScanPlayViewModel.kt` | QR scan → playback state machine |
| `HomeScreen.kt` / `ScanScreen.kt` / `PlaybackScreen.kt` | Compose screens |
| `scripts/build_deck.py` | Standalone per-person deck builder: playlist fetch, year lookup, QR/PDF generation |
| `scripts/make_contrast.py` | Photo → posterized portrait (`face.png`) for the QR codes, plus `photo-contrast.png` |
| `people/<slug>/` | Everything person-specific, each its own private repo; one Gradle flavor per directory (see top of `app/build.gradle.kts`) |
